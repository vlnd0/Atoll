# Форк Atoll — план работ

Личный форк [Ebullioscopic/Atoll](https://github.com/Ebullioscopic/Atoll).
Апстрим: `upstream/dev` (дефолтная ветка апстрима — `dev`, не `main`).

**Две цели, и они в конфликте, поэтому разведены по веткам:**

1. Общеполезные исправления уходят PR'ами в апстрим — их не надо тащить вечно.
2. Личные настройки сборки и фичи живут отдельно и в PR'ы не попадают.

Правило, из которого всё следует: **ветка, предназначенная для PR, не должна содержать
ни одной строки, специфичной для моей машины или моего вкуса.** Если хочется и того и
другого в одном месте — значит нужна опция в настройках, а не хардкод.

## 1. Модель веток

```
upstream/dev ────────────────────────────────────────►  (апстрим, только читаем)
     │
     ├── up/usage-parser-perf ──┐
     ├── up/gate-privacy-start ─┤  PR-кандидаты: чистые, узкие,
     ├── up/tabbar-position ────┤  дефолты не меняют поведение
     │                          │
     ├── mine/thin-build ───────┤
     ├── mine/no-sparkle ───────┤  личное: никогда не в PR
     ├── mine/defaults ─────────┤
     ├── mine/cyclop-translate ─┤
     ├── mine/cyclop-snippets ──┤
     └── mine/cyclop-vault ─────┤
                                ▼
                          personal  ◄── интеграционная, отсюда собираю
```

- `dev` — зеркало апстрима. Прямых коммитов нет никогда.
- `up/*` — ветвятся от `upstream/dev`, одна тема на ветку, готовы к `gh pr create`.
- `mine/*` — ветвятся от `upstream/dev` тоже (не от `personal`), чтобы их можно было
  пересобирать в любом порядке.
- `personal` — сюда мержатся все `up/*` и `mine/*`. Собираю только с неё.

Обновление:

```bash
git fetch upstream
git checkout dev && git merge --ff-only upstream/dev
git checkout personal && git merge dev          # затем перемержить топики при конфликтах
```

Когда PR принимают в апстрим, его ветка растворяется в `dev` при следующем мерже —
содержимое идентично, конфликта нет. Ветку `up/*` после этого удаляю.

## 2. PR-кандидаты в апстрим

### PR-1 · `up/usage-parser-perf` — счётчик токенов не перечитывает всё подряд

**Проблема.** `JSONLUsageParser.aggregate` (`DynamicIsland/managers/LLMUsage/JSONLUsageParser.swift:78-108`)
на каждом обновлении читает **все** `.jsonl` из `~/.claude/projects` целиком в память
через `String(contentsOf:)`, JSON-парсит каждую строку и только потом отбрасывает
записи старше недели (строка 94, после `parseLine`). Кэша нет, фильтра по mtime нет.

На реальном рабочем каталоге это 90 МБ в 72 файлах при каждом открытии таба
(троттлинг 60 с в `LLMUsageManager.swift:14`). В окно недели попадают единицы файлов.

**Правка.**
- Отфильтровать `files` по `contentModificationDate >= weekStart` до цикла.
- Читать построчно вместо загрузки файла целиком.
- Ранний выход по timestamp до `JSONSerialization`, где формат позволяет.

**Почему возьмут.** Чистый выигрыш, поведение не меняется, дефолтов не трогает.
Пользы тем больше, чем активнее человек пользуется Claude Code.

**Риск.** `weekStart` считается от `now`; файл, дописанный давно, но с записями внутри
окна, отфильтруется корректно (mtime ≥ момента последней записи). Обратный случай —
файл тронут недавно, но записи старые — отсеется уже существующей проверкой на строке 94.

### PR-2 · `up/gate-privacy-start` — безусловные старты за флаги

**Проблема.** В `applicationDidFinishLaunching` (`DynamicIsland/DynamicIslandApp.swift:617`)
часть менеджеров стартует независимо от настроек, хотя флаги под них уже есть:

| Строка | Что | Флаг |
|---|---|---|
| :684 | `PrivacyIndicatorManager.startMonitoring()` | `enableCameraDetection` / `enableMicrophoneDetection` есть, но не проверяются |
| :653 | `idleAnimationManager.initializeDefaultAnimations()` | грузит Lottie даже когда анимации выключены |
| :630 | `extensionXPCServiceHost.start()`, `extensionRPCServer.start()` | `enableThirdPartyExtensions` есть, не проверяется |

Соседние вызовы (`:674` ScreenRecording, `:679` DND) уже загейчены — то есть это
недосмотр, а не замысел.

**Правка.** Обернуть в `if Defaults[...]` по образцу соседних строк + подписки на
изменение флага, чтобы включение в настройках поднимало менеджер без перезапуска.

**Почему возьмут.** Приводит код к его же собственному соглашению. Дефолты не меняются,
поведение из коробки идентично.

**Явно НЕ трогаем в этом PR:** `MemoryUsageMonitor` (`:765`). Он сторож, ему положено
работать всегда — см. §5.

### PR-3 · `up/tabbar-position` — положение таб-бара опцией

Идея, которая делает главную личную хотелку общеполезной: не переносить таб-бар влево
хардкодом, а добавить настройку.

**Новые ключи в `DynamicIsland/models/Constants.swift`:**

```swift
enum TabBarPosition: String, Defaults.Serializable { case top, left }
static let tabBarPosition = Key<TabBarPosition>("tabBarPosition", default: .top)
static let tabSwitchOnHover = Key<Bool>("tabSwitchOnHover", default: false)
```

Оба дефолта сохраняют текущее поведение — апстриму нечего терять.

**Правки:**

| Файл | Что |
|---|---|
| `components/Tabs/TabSelectionView.swift:117` | `HStack` → `HStack`/`VStack` по `tabBarPosition`; в вертикальном режиме иконки без подписей, капсула → `RoundedRectangle` |
| `components/Notch/DynamicIslandHeader.swift:50` | рендерить `TabSelectionView()` только при `.top` |
| `ContentView.swift:1084` | при `.left` обернуть `switch coordinator.currentView` в `HStack { rail; pane }` |
| `sizing/matters.swift:99` | `recommendedMinimumNotchWidth` — при `.left` не раздувать ширину под число табов, добавить фиксированные ~44pt на рейл |

**Побочный выигрыш, который стоит указать в описании PR.** Сейчас при 6+ табах
`recommendedMinimumNotchWidth` принудительно растягивает открытую чёлку до 770pt
(`matters.swift:99-103`), иначе горизонтальные табы не помещаются. Вертикальный рейл
снимает это ограничение: 30pt сбоку вместо ~130pt по ширине.

**Переключение по наведению** (`tabSwitchOnHover`) портируется из `Rail` Cyclop
(`Sources/Cyclop/UI/NotchContentView.swift:187-246`): задержка 150 мс через `.task(id:)`,
чтобы курсор, пролетающий мимо, не дёргал табы. Тоже за флагом, по умолчанию выключено.

**Риск.** Это единственная правка в двух горячих файлах апстрима (`ContentView.swift`,
`TabSelectionView.swift`). Если PR не примут — конфликты при каждом крупном релизе,
минут по 15-30. Если примут — конфликтов нет вовсе. Отсюда и весь смысл делать опцией.

**Ограничение.** Открытая чёлка — 200pt по высоте (`matters.swift:35`), иконка ~28pt.
Одна колонка держит ~7 табов. У меня их 5 (см. §4), запас есть. В PR добавить
`ViewThatFits` или заметку в описании, что при большем числе табов рейл переполнится —
Cyclop поэтому разносит иконки на два рейла.

## 3. Личные ветки

Ничего отсюда в PR не уходит.

### `mine/thin-build`

| Правка | Выигрыш |
|---|---|
| `ARCHS = arm64` | −14.5 МБ (сейчас fat: x86_64 + arm64, 29 МБ) |
| `SWIFT_OPTIMIZATION_LEVEL = -Osize` (в Release сейчас дефолтный `-O`) | 5–15% с `__text` |
| Локали: оставить `en` + `ru` из 14 | ~−3 МБ |
| Прополоть `Assets.xcassets` | до −2 МБ |

**Не для апстрима:** Atoll заявляет macOS 14+ и работает на Intel-маках в режиме
Dynamic Island без физической чёлки. `arm64`-only ломает это для чужих людей.

Замеренный состав `Atoll.app` v2.3.3 — 44 МБ:

```
MacOS/Atoll     29 MB   fat binary, __text 10.9 MB на арку
Resources      8.2 MB   Assets.car 5.1, 14 локалей, timer.mp3 196K, dynamic.m4a 124K
Frameworks     7.6 MB   Lottie 4.6, Sparkle 3.0
```

Цель: **12–15 МБ**.

### `mine/no-sparkle`

Выкинуть Sparkle из зависимостей и `Updates/`. −3 МБ и минус фоновая проверка.

**Это не косметика, а обязательное.** Appcast форка указывает на релизы апстрима —
первое же автообновление тихо заменит мою сборку ванильным Atoll со всеми моими
настройками поверх.

### `mine/defaults`

Стартовый набор флагов. Оставляем включённым только нужное:

**Включено:** медиаплеер, календарь, полка файлов, счётчик токенов (Claude + Codex,
квоты включены), буфер обмена в режиме попапа из шапки, виджеты локскрина.

**Выключено:** замена системных HUD (громкость/яркость/подсветка), индикаторы
приватности (камера/микрофон/запись экрана/DND/CapsLock), батарея и Bluetooth/AirPods,
Stats, Terminal, Timer как таб, Notes, пипетка, Screen Assistant, сторонние расширения,
интеграции BetterDisplay/Lunar/DDC, idle-анимации.

Побочно снимается: опрос Bluetooth раз в 3 с (`BluetoothAudioManager.swift:212`),
фолбэк-опрос яркости раз в 0.15 с (`SystemMediaControllers.swift:778`).

Опрос пастборда раз в 0.5 с (`ClipboardManager.swift:220`) **остаётся** — буфер нужен,
и от него зависит vault скриншотов.

### `mine/cyclop-translate`

Порт офлайн-перевода EN↔RU из Cyclop. Новые файлы, поэтому мержу не мешает.

Источники: `Sources/Cyclop/Services/Translator.swift` (135 строк),
`Sources/Cyclop/UI/TranslatePane.swift` (242).

Работает на системном фреймворке `Translation` (macOS 15) — ноль веса в бандле,
ноль сети, языковые пакеты качает сама система по запросу.

**Клавиатурный ввод — полный, как в Cyclop.** Оказалось дешевле, чем думал: главное
окно Atoll уже `NSPanel` со стилем `[.borderless, .nonactivatingPanel]`
(`DynamicIslandApp.swift:407`) и `canBecomeKey: true` (`DynamicIslandWindow.swift:61`) —
тот же класс окна, что у Cyclop, и таб Terminal уже принимает ввод.

Портировать нужно только две вещи из `Sources/Cyclop/Notch/NotchPanel.swift`:

1. **Диспетчер ⌘A/X/C/V/Z по кодам клавиш** (`NotchPanel.swift:61-90`). Приложение —
   `LSUIElement` (`project.pbxproj:605`), меню-бара нет, поэтому Edit-шорткаты сами до
   текстового поля не доходят. Критично матчить **keyCode, а не символ**: в кириллице
   ⌘C приходит как «с» (U+0441), сравнение со строкой `"c"` молча не срабатывает.
2. **Гейт `acceptsKeyboard`** (`NotchPanel.swift:12-28`) — забирать фокус только пока
   открыт таб перевода, иначе панель гасит каретку в том, где человек работает.

**Автозакрытие:** пока фокус в поле ввода — чёлка не закрывается по уводу курсора.
Закрытие по Esc или клику мимо.

### `mine/cyclop-snippets`

Библиотека заготовок текста. Свой таб в рейле.
Источники: `Services/SnippetStore.swift` (132), `UI/SnippetsPane.swift` (269).
Хранение — простой файл, редактируемый снаружи (в Cyclop есть пункт меню
«Show Snippets File»).

### `mine/cyclop-vault`

Автосохранение картинок из буфера в папку, счётчик занятого места, очистка.
Источник: `Services/ScreenshotVault.swift` (81 строка).
Зависит от включённого `ClipboardManager` — учтено в `mine/defaults`.

## 5. Память

**Что известно точно.** `MemoryUsageMonitor` (`DynamicIsland/managers/MemoryUsageMonitor.swift`)
раз в 8 секунд проверяет собственный RSS и при превышении **1 ГБ** (`:30`) предлагает
перезапустить приложение (`:69-78`). То есть авторы встроили в релизную сборку сторож
собственной утечки.

**Чего не известно.** Где именно течёт. По чтению кода не видно — нужен профайлинг.
Кандидаты по объёму кода и характеру работы: `FullScreenArtworkWindowManager` (67 КБ),
`MusicManager` (64 КБ), `AnimatedArtworkManager`, кэши обложек.

**Порядок действий — сначала замерить.**

1. Собрать с моим набором флагов (§3, `mine/defaults`).
2. Прогнать день под Instruments: Leaks + Allocations, с упором на смену треков и
   открытие/закрытие чёлки.
3. Зафиксировать RSS в начале и через сутки.

**Вполне возможно, что с выключенными фичами утечки не будет вовсе** — большая часть
подозреваемых относится к тому, что я и так отключаю. Тогда работа закончится на замере.

Если утечка найдётся и окажется в общем коде — это **PR-4 в апстрим**, самый ценный из
всех. Чинить вслепую до профайлинга не буду: без воспроизведения нельзя проверить, что
починил.

## 6. Отзывчивость

Требование отдельное от «лёгкости», и упирается оно **не** в таймеры и не в размер
бандла, а в область инвалидации SwiftUI.

### Диагноз

`ContentView.swift` — 3000+ строк, и на нём висит **58** реактивных свойств:
16 `@ObservedObject` на синглтоны-менеджеры (строки 42-57) и 40+ `@Default`.

В SwiftUI это означает: **любое** изменение `@Published` в **любом** из этих 16
менеджеров инвалидирует тело всего `ContentView` целиком.

Конкретный горячий путь. `MusicManager` держит 28 `@Published` свойств, среди них
`elapsedTime` (`MusicManager.swift:497`), которое обновляется на каждом репорте позиции
воспроизведения (`:850`). `ContentView` наблюдает `musicManager` на верхнем уровне
(`ContentView.swift:43`). Итого: **пока играет музыка, вся чёлка пересобирается на каждый
тик позиции** — включая полку, календарь, счётчик токенов и всё остальное, что к музыке
отношения не имеет.

Побочно: `statsManager` (`:47`), `privacyManager` (`:49`), `capsLockManager` (`:52`)
наблюдаются даже когда соответствующие фичи выключены. Выключенный менеджер не публикует,
так что это не расход — но и не помогает.

### Что с этим делать

Правильное лечение — вынести потребителей частых обновлений в отдельные маленькие вьюхи,
которые наблюдают менеджер сами. Тогда тик позиции перерисовывает скраббер, а не всю
чёлку. Это стандартный приём, и он же — самый ценный PR из всех возможных здесь.

**Но это рефакторинг в самом горячем файле апстрима.** Поэтому порядок такой:

1. **Сначала замерить.** Instruments → SwiftUI (счётчики `View Body`) + Time Profiler.
   Открыть чёлку, включить музыку, посмотреть сколько раз в секунду пересобирается тело
   и сколько это стоит. Без цифры нет смысла трогать 3000 строк.
2. **Точечная экстракция, не переписывание.** Вынести только тех потребителей, что
   реально дают churn по замеру — скорее всего скраббер позиции и лирику. Диф на
   100-200 строк вместо тысячи.
3. **Отправить как PR-5.** Если примут — расхождения нет вовсе. Если нет — это третий
   файл в списке конфликтующих, и надо честно решать, стоит ли оно того.

Не начинать с этого пункта: пока нет `build.sh`, каждая итерация профайлинга — ручной
заход в Xcode.

### Компромисс `-Osize` против `-O`

`-Osize` из §3 экономит 5-15% размера кода, но оптимизирует по размеру, а не по скорости
— на горячих путях это может стоить нескольких процентов производительности. Для UI-
приложения обычно незаметно (лучшая локальность i-кэша часто перекрывает потери), но раз
требования два сразу — не угадывать, а замерить оба варианта на шаге 3 из §8 и оставить
тот, что лучше по факту.

Дополнительно стоит попробовать `LLVM_LTO = YES` для Release — сейчас не выставлен,
а помогает обоим требованиям сразу. `SWIFT_COMPILATION_MODE = wholemodule` уже включён
(`project.pbxproj:568`).

## 7. Сборка и подпись

**Самоподписанный сертификат, общий для обоих Маков.**

Разрешения macOS (Accessibility, Календарь, Запись экрана) привязаны к сигнатуре кода.
Ad-hoc подпись даёт новый cdhash при каждой сборке — система будет заново спрашивать все
доступы после каждой пересборки. Стабильный сертификат решает это раз и навсегда.

```
1. Keychain Access → Certificate Assistant → Create a Certificate
   Name: Atoll Personal · Type: Code Signing · Self Signed Root
2. Экспорт .p12 → импорт на втором Маке
3. Доверие: Always Trust для Code Signing
4. build.sh: CODE_SIGN_IDENTITY="Atoll Personal"
```

**`scripts/build.sh`** (личная ветка): собрать Release, подписать, упаковать `.dmg`,
`gh release create` в форк.

**Доставка на второй Мак:** локальная сборка → GitHub Releases → скачал и положил в
`/Applications`. Xcode на втором Маке не нужен.

Почему не CI: ассеты Releases бесплатны и не считаются против квоты репозитория (лимит
2 ГБ на файл, нам нужно ~12 МБ), **но macOS-раннеры GitHub Actions тарифицируются
всегда — $0.062/мин, даже на публичных репозиториях.** Сборка Atoll — 10–20 минут,
то есть ~$0.6–1.2 за прогон. Локальная сборка даёт то же самое бесплатно.

Форк публичный — форки публичных репозиториев приватными быть не могут. В репо не
попадает ничего личного, кроме этого файла и списка флагов.

## 9. Критерии готовности

**Лёгкость**
- [ ] `.app` ≤ 15 МБ
- [ ] RSS стабилен за сутки работы, сторож на 1 ГБ не срабатывает

**Отзывчивость**
- [ ] Тело `ContentView` не пересобирается на каждый тик позиции воспроизведения
- [ ] Открытие чёлки без просадок кадров (Instruments → Animation Hitches)
- [ ] Открытие таба Usage не читает 90 МБ (Instruments → File Activity)
- [ ] Вариант оптимизации (`-O` / `-Osize` / LTO) выбран по замеру, а не по умолчанию

**Мержабельность**
- [ ] Обе машины: разрешения выданы один раз и переживают пересборку
- [ ] `git merge upstream/dev` конфликтует максимум в 2 файлах, и только пока PR-3 висит
- [ ] PR-1 и PR-2 отправлены

## 10. Что решено и почему

| Вопрос | Решение |
|---|---|
| Глубина форка | Тонкий: конфиг + новые файлы + рейл. Фичи не вырезаем — выключенное и так не запускается, а demand paging делает неиспользуемый код почти бесплатным в рантайме |
| Рейл | Один слева, 30pt |
| Переключение табов | По наведению, задержка 150 мс |
| Квоты токенов | Включены, с чтением кредов |
| Sparkle | Выкинуть |
| Системные перехваты | Только виджеты локскрина |
| Порт из Cyclop | Перевод, сниппеты, vault скриншотов |
| Ввод в чёлке | Полный, с клавиатуры |
| Сниппеты | Свой таб |
| Буфер | Попап из шапки |
| Подпись | Самоподписанный сертификат |
| Доставка | Локальная сборка → GitHub Releases |
| Утечка памяти | Сначала профайлинг, потом правка |
| Отзывчивость | Главный рычаг — область инвалидации SwiftUI, а не таймеры. Сначала замер, потом точечная экстракция вьюх |
